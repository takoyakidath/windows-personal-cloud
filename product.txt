# Windows Personal Cloud

## 1. Project Overview

Windows PCを単なる個人用PCではなく、

* Windows Workstation
* Gaming PC
* Development Server
* Personal Cloud
* Remote Computer
* Home Server

として利用できるようにする。

Windowsを再インストールしても、GitHub上の設定・スクリプトから環境を再構築できるようにする。

目標は、

> 「PCを壊しても、Windowsを入れ直しても、GitHubから環境を再構築できる」

状態。

---

# 2. Goals

## 2.1 Environment as Code

PCの環境を可能な限りコード・設定ファイルとして管理する。

GitHub Repositoryを環境構築のSource of Truthとする。

管理対象:

* Windows設定
* インストールするアプリ
* WSL2
* Docker
* Workspace
* Windows Firewall
* SSH
* SMB
* Tailscale
* Parsec
* winctl
* Discord Bot
* Raspberry Pi Controller
* サーバー設定
* 自動起動設定
* Scheduled Tasks
* Backup設定

---

## 2.2 Rebuildable

Windowsを完全に再インストールした場合でも、

```text
Windows Install
    ↓
Win + R
    ↓
Bootstrap
    ↓
GitHub
    ↓
自動セットアップ
    ↓
Windows PC完成
```

という流れで復旧できるようにする。

---

## 2.3 Remote First

外出先やMacからWindows PCを操作できるようにする。

主なアクセス方法:

* Tailscale
* SSH
* Windows App / RDP
* Parsec
* SMB

インターネットへ直接、

* RDP
* SSH
* SMB
* Docker API
* 管理画面

などを公開しない。

基本的にTailscaleまたはLAN経由でアクセスする。

---

## 2.4 Low Power

Windows PCを24時間起動し続ける必要がないようにする。

必要がない時間帯は、

* WSL2
* Docker
* サーバー
* SMB
* SSH
* Parsec
* その他不要なサービス

を停止し、最終的にはWindowsをHibernateへ移行する。

必要になったらRaspberry PiからWake-on-LANで起動する。

---

# 3. Core Concept

システムを以下の4つに分離する。

```text
GitHub
    │
    │ Configuration / Scripts
    ▼
Windows PC
    │
    ├── Workstation
    ├── Gaming
    ├── WSL2
    ├── Docker
    ├── Workspace
    └── Services

Raspberry Pi
    │
    ├── Discord Controller
    ├── Wake-on-LAN
    ├── Health Check
    └── Windows Boot Monitor
```

役割:

```text
GitHub
= PCの設計図

Windows
= 実際のコンピューティング

Raspberry Pi
= Always-on Controller

Discord
= Remote Control Interface
```

# 5. Always-on Controller

## 5.1 Raspberry Pi

使用していないRaspberry PiをWindows PCのControllerとして利用する。

Raspberry Piは常時稼働する。

ただし、高負荷な処理は行わない。

主な役割:

* Discord Bot
* Wake-on-LAN
* Windows PCの状態確認
* Windows起動確認
* Health Check
* Boot Monitor
* ログ管理

---

## 5.2 Raspberry Piの役割

Raspberry PiはWindows PCそのものを置き換えるものではない。

あくまで、

> Windows PCが寝ているときでも動作できる「リモコン」

として利用する。

```text
Discord
   ↓
Raspberry Pi
   ↓
Windows PC
```

---

## 5.3 Raspberry Pi Directory

Repository内では、将来的に以下のような構成を想定する。

```text
controller/
├── README.md
├── bot/
├── wake/
├── health/
├── config/
└── install.sh
```

# 6. Discord Controller

DiscordをWindows PCのRemote Control Interfaceとして利用する。

Raspberry Pi上でDiscord Botを動作させる。

Windows PCがHibernateしていてもDiscord Botは動作し続ける。

---

## 6.1 Commands

最小構成:

```text

/win wake
```

将来的に:

```text

/win game
/win work
/win server
/win update
/win reboot
/win shutdown
/win doctor
```

を追加する。

---

## 6.2 Security

Discord Botから任意のPowerShellやShellコマンドを実行できるようにはしない。

実行可能な操作をAllowlist方式で管理する。

Discord User IDまたはRoleによって実行権限を制限する。

# 8. `/win wake`

Windows PCを起動する。

処理:

```text

    ↓

    ↓

    ↓
すでに起動
    ↓

```

停止・Hibernate中の場合:

```text

    ↓

    ↓

    ↓

    ↓

    ↓
Network確認
    ↓
Tailscale確認
    ↓
SSH確認
    ↓
WSL2 / Docker確認
    ↓
Health Check
    ↓

```

# 9. Wake-on-LAN

Alienware m17 R3の内蔵RJ45 Ethernetを第一候補とする。

USB Ethernet Adapterではなく、可能な限り本体内蔵Ethernetを利用する。

Raspberry PiからMagic Packetを送信する。

---

## 9.1 WoL検証

実装前に実機で以下を確認する。

1. WindowsからHibernate
2. Raspberry PiからWake-on-LAN
3. Alienwareが起動するか確認
4. Windows起動後にネットワークが復帰するか確認
5. Tailscaleが復帰するか確認

HibernateからWake-on-LANできるかは実機で検証する。

---

# 10. BIOS Configuration

Alienware m17 R3のBIOSで以下を確認する。

* Wake on LAN
* USB Wake Support
* Deep Sleep Control
* AC Wake
* Auto Power On
* Ethernet Wake関連設定

必要なものだけ有効化する。

不要なWake設定は有効化しない。

---

---

## SERVER

## SLEEP


# 21. Game Detection

ゲーム起動中かどうかを確認する。

ゲームは設定ファイルで管理する。

例:

```text
config/games.json
```

```json
{
  "games": [
    "game.exe",
    "another-game.exe"
  ]
}
```

未知のプロセスを勝手にゲーム扱いしない。

---

# 22. Automatic Hibernate

21:00にゲームが起動していなければ、

```text
winctl sleep
```

を実行する。

`winctl sleep`では、Hibernate前に必要な停止処理を行う。

例:

```text
Check active games
        ↓
Check backup
        ↓
Check important processes
        ↓
Stop Docker
        ↓
Stop WSL2
        ↓
Stop unnecessary services
        ↓
Prepare Windows
        ↓
Hibernate
```

---

# 23. Safety Check

以下の状態では自動Hibernateを行わないことを検討する。

* ゲーム起動中
* Backup実行中
* Windows Update中
* 重要な処理実行中
* ファイルコピー中
* Dockerで重要なJob実行中
* ユーザーが明示的に禁止している場合

---

# 24. Hibernate

最終的なNight ModeではWindows Hibernateを第一候補とする。

目的:

* CPU負荷を停止
* GPU負荷を停止
* WSL2停止
* Docker停止
* ファン停止
* ディスプレイ停止
* 消費電力削減

ただし、Wake-on-LANがHibernateから正常に動作するかを実機で検証する。

---

# 25. Power State Fallback

WoLの対応状況によって使用するPower Stateを変更可能にする。

優先順位:

```text
1. Hibernate + Wake-on-LAN
2. Sleep + Wake-on-LAN
3. その他の低電力状態
4. Shutdown + 手動Power On
```

設定ファイルから変更可能にする。

例:

```text
night_mode = hibernate
```

# 45. Design Principles

このプロジェクトでは以下を原則とする。

1. GitHubをEnvironment DefinitionのSource of Truthとする。
2. SecretをGitHubへ保存しない。
3. Installerは何度実行しても壊れないようにする。
4. Installerは再起動後にResumeできるようにする。
5. 重要なデータを自動削除しない。
6. Remote AccessはTailscaleを基本とする。
7. RDP/SSH/SMBをInternetへ直接公開しない。
8. Raspberry PiはAlways-on Controllerとして使用する。
9. Raspberry Piでは重い処理を行わない。
10. Windows PCは必要なときだけ起動する。
11. 21:00にゲーム中でなければHibernateする。
12. WakeはDiscordから手動で行う。
13. Wake-on-LANはAlienware m17 R3の実機で検証する。
14. WoLが利用できない場合は別のPower Stateを検討する。
15. Discordから任意のShellコマンドを実行できるようにしない。
16. 最初から過剰な複雑性を導入しない。
17. すべての機能は段階的に追加する。
