# Windows Personal Cloud

## 目的

Windows PCを、自分専用の
・リモートWindows
・ゲームPC
・開発環境
・Linuxサーバー
・個人クラウド
として運用する。

最重要目標は、

「Windowsを再インストールしても、
ほぼワンクリックで元の環境を再構築できる」

こと。

---

# Bootstrap

最重要コンポーネント。

Windows初期状態から実行できる。

Bootstrapの責務:

1. GitHub repositoryを取得
2. repositoryのrevisionを確認
3. 管理者権限を確認
4. OS / architectureを確認
5. storageを検出
6. configurationを読み込む
7. installerを実行
8. 必要に応じて再起動
9. 再起動後に自動的に続行
10. 最終health check

途中で失敗しても、
再実行することで続きから実行できる設計にする。

---

# Idempotency

非常に重要。

すべてのinstaller/scriptは
複数回実行しても壊れないこと。

例:

Gitが既に存在
→ skip

WSL2が既に有効
→ skip

Dockerが既に存在
→ skip

Workspaceが既に存在
→ skip

設定済み
→ skip

必要ならrepairする。

---

# Storage

Workspaceのパスはハードコードしない。

例:

D:\Workspace

ただしPCによってD:が存在しない可能性がある。

そのため、

config/workspace.json

などで設定可能にする。

候補:

D:\Workspace
E:\Workspace
custom path

# SMB

Windows側:

D:\Workspace

↓

SMB Share:

Workspace

Macからアクセス:

smb://<windows-host>/Workspace

LANでは直接アクセス。

遠隔ではTailscale経由。

TCP 445をInternetへ公開しない。

SMBはバックアップではない。

# Modes

READY
GAME
WORK
SERVER
SLEEP
DEGRADED
ERROR

状態遷移を管理する。

GAME:

不要なserver/serviceを停止可能。

WORK:

開発・Adobe等のWindows作業を優先。

SERVER:

Docker services等を優先。

SLEEP:

実際のWindows Sleepではなく、
不要なサービスを停止したidle状態を基本とする。

# Reboot Handling

Windows設定によっては再起動が必要になる。

再起動後に、

「どこまで終わったか」

を自動判定して続きを実行する。

state fileなどを利用してよい。

例:

bootstrap-state.json

{
  "windows": "completed",
  "wsl": "completed",
  "docker": "completed",
  "tailscale": "pending"
}

# Development Policy

Claude Codeはこのproduce.txtを仕様書として扱う。

実装時は、

1. 現在のWindows環境を調査
2. 小さいscriptから実装
3. 手動で動作確認
4. idempotency確認
5. error handling追加
6. test追加
7. bootstrapへ統合
8. 最後にinstaller化

の順番で進める。

一度に巨大なinstallerを作らない。
